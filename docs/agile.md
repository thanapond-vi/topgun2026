## 1. ทบทวน Scrum แบบสั้นที่สุด

Scrum คือการทำงานเป็นรอบสั้น ๆ (**Sprint**) แต่ละรอบต้องได้ของที่ "ใช้งานได้จริง" มาดู แล้วปรับแผนจากของจริง ไม่ใช่วางแผนครั้งเดียวแล้วทำยาวจนจบ

### 3 บทบาท

| บทบาท | หน้าที่ | ในทีมเรา |
|---|---|---|
| Product Owner (PO) | ตัดสินว่าอะไรสำคัญก่อน เรียงลำดับ backlog | PM |
| Scrum Master (SM) | ดูแลให้ทีมทำตามวิธี ปลดสิ่งที่ขวางทาง (blocker) | PM (ทีมเล็ก รวมกันได้) |
| Developers | ลงมือทำ ประเมินงาน เลือกงานเอง | June, Jeff (Track 1) · Boss, Peach (Track 2) · Phu (Track 3) |

### 3 เอกสาร (Artifacts)

| ชื่อ | คืออะไร | ที่อยู่ |
|---|---|---|
| Product Backlog | รายการงานทั้งหมดของโปรเจกต์ เรียงตามความสำคัญ | `sprint-board.csv` ทุกแถว |
| Sprint Backlog | งานที่ทีมรับมาทำใน Sprint นี้ | แถวที่คอลัมน์ `sprint` = Sprint ปัจจุบัน |
| Increment | ของที่ใช้งานได้ตอนจบ Sprint | demo ใน Sprint Review |

### 5 กิจกรรม (Events)

| กิจกรรม | เมื่อไร | นานเท่าไร | ทำอะไร |
|---|---|---|---|
| Sprint Planning | วันแรกของ Sprint | 30–45 นาที | เลือกงานจาก backlog ตั้ง Sprint Goal แตกเป็น task |
| Daily Scrum | ทุกวัน เวลาเดิม (เสนอ 21:00 ออนไลน์) | **15 นาที** | แต่ละคนตอบ 3 ข้อ แล้วอัปเดตตาราง |
| Sprint Review | วันสุดท้ายของ Sprint | 30 นาที | demo ของจริง ไม่ใช่สไลด์ |
| Sprint Retrospective | ต่อจาก Review | 15 นาที | อะไรดี / อะไรควรแก้ / จะลองอะไรรอบหน้า |
| Backlog Refinement | ระหว่าง Sprint ตามต้องการ | 15 นาที | แตกงานใหญ่ ประเมินงานใหม่ |

**Daily Scrum 3 คำถาม** (ตอบคนละไม่เกิน 2 นาที เรื่องลึกค่อยคุยต่อหลังประชุม)
1. เมื่อวานทำอะไรเสร็จ
2. วันนี้จะทำอะไร
3. มีอะไรติด (blocker) ที่ต้องให้คนอื่นช่วย

## 3. วิธีแตกงาน (Split Task)

### ระดับของงาน

```
Epic (งานใหญ่ระดับ Track)
 └─ User Story (สิ่งที่ผู้ใช้/ทีมได้ประโยชน์ 1 อย่าง)
     └─ Task (งานลงมือ 1 คน ≤ 1 วัน)
```

ตัวอย่าง:
- **Epic:** Track 2 ตรวจคุณภาพเมล็ด
- **Story:** "ในฐานะ Track 3 ฉันต้องการสัดส่วนเมล็ดเสียเป็น JSON เพื่อใช้ตั้งราคา"
- **Tasks:** ตัดภาพเป็นรายเม็ด → เทรน classifier → นับเม็ดต่อคลาส → ส่ง JSON ผ่าน API/MQTT

### กฎการแตกงาน

1. **ขนาด**: ใช้ขนาด S / M / L แทน story point เพราะ Sprint สั้น
   - S = ≤ 2 ชม. · M = ≤ ครึ่งวัน · L = ≤ 1 วัน
   - งานที่ใหญ่กว่า L **ต้องแตกก่อน** รับเข้า Sprint
2. **แตกแบบแนวตั้ง (vertical slice)**: แต่ละชิ้นควรได้ผลที่ทดสอบได้ เช่น "อ่านค่า ADC แล้ว print ได้" ดีกว่า "เขียนครึ่งแรกของโค้ด"
3. **1 task = 1 เจ้าของ** งานคู่ให้ระบุคนหลักคนเดียว
4. **ทุก task มีเกณฑ์เสร็จ** (ดูข้อ 4) ถ้าบอกไม่ได้ว่าเสร็จเมื่อไร แปลว่ายังแตกไม่พอ
5. **WIP limit**: คนละไม่เกิน 2 งานในสถานะ Doing พร้อมกัน ทำให้เสร็จก่อนเริ่มงานใหม่

### สถานะบนบอร์ด

```
Backlog → To Do → Doing → Review → Done
                     ↘ Blocked (ระบุเหตุในคอลัมน์ note)
```

- **Review** = ให้เพื่อนอีกคนลองรันตามเอกสาร ถ้ารันได้จึงเลื่อนเป็น Done
- **Blocked** ต้องพูดใน Daily Scrum ทุกครั้ง PM รับผิดชอบปลดล็อก

## 4. Definition of Done (ใช้ร่วมทุกงาน)

- [ ] รันได้บนอุปกรณ์จริง (ESP32 / Pi 5 / โน้ตบุ๊ก) ไม่ใช่แค่บนเครื่องตัวเอง
- [ ] โค้ดอยู่ใน Git และมี README สั้น ๆ บอกวิธีรัน
- [ ] คนอื่นในทีมรันตามได้ (ผ่าน Review)
- [ ] ใช้ได้แบบ **ไม่มีอินเทอร์เน็ต** (เตรียม wheel / โมเดล / ไลบรารีไว้ในเครื่อง)
- [ ] อัปเดตสถานะในตารางแล้ว

## 6. วิธีอัปเดตตารางทุกวัน (สำหรับ PM)

1. ก่อน Daily Scrum: เปิด `sprint-board.csv` กรองคอลัมน์ `sprint` = Sprint ปัจจุบัน
2. ระหว่างประชุม: แต่ละคนเลื่อน `status` ของงานตัวเอง และใส่ `note` ถ้า Blocked
3. หลังประชุม: PM นับงาน Done/ทั้งหมด ของ Sprint (ช่วง PREP ใช้ดูว่างานเตรียมตัวทันวันที่ 15 ไหม) เพื่อดูว่าทันไหม (burndown แบบง่าย)
   - ถ้าครึ่ง Sprint แล้ว Done < 40% → ตัดงาน "Could" ออก อย่าเพิ่มเวลา
4. จบ Sprint: งานที่ไม่เสร็จกลับไปที่ Backlog แล้วเรียงใหม่ใน Planning รอบหน้า

ลำดับความสำคัญในคอลัมน์ `priority` ใช้ **MoSCoW**: Must (ต้องมี) / Should (ควรมี) / Could (ถ้ามีเวลา)
